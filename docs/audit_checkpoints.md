# نقاط تحقق سلسلة التدقيق خارج القاعدة

سلسلة التجزئة تكشف تعديل صف مسجل، لكنها لا تمنع من يملك سلطة إدارية كاملة من إعادة بناء السلسلة كلها. نقطة التحقق الخارجية تغلق ذلك:
1. يوميًا، مهمة بدور الخدمة تقرأ `app.audit_head()` (رقم التسلسل والبصمة).
2. تكتب السطر إلى مخزن خارج القاعدة وخارج صلاحيات المنصة: مستودع خاص بصلاحية إضافة فقط، أو بريد إلى صندوق المؤسس.
3. `audit_verify()` يُشغَّل مقابل آخر نقطة: إن تغيّرت بصمة رقم تسلسل سبق تسجيله فالسلسلة أُعيد بناؤها.

ما لا تثبته السلسلة وحدها: أن كل أثر سُجل، وأن `actor_id` صحيح. منذ 1.8 (الترحيل 0010، الادعاء A15) يسجل المحفّز `audit_effect` كل قرار موافقة وكل تغيّر في الصندوق الصادر والنشر ونشر الإنتاج داخل معاملة الأثر نفسها وبهوية فاعلها الحقيقية، وسياسات الإدراج تمنع أي جلسة من الكتابة باسم غيرها. (تصحيح: نسخة 1.7 من هذه الوثيقة أحالت إلى ادعاء «C12.14» غير موجود في المصفوفة؛ الادعاءان الصحيحان A15 وA15b.)

## الأداة (1.8، الادعاء A15b)

```
psql -Atc "select chain_seq, hash from app.audit_head()"            # بدور الخدمة
AUDIT_CHECKPOINT_KEY=... python tools/audit_checkpoint.py append --store checkpoints.jsonl --seq N --hash H
psql -Atc "select chain_seq, hash from app.audit_log where chain_seq in (...)" > hashes.tsv
AUDIT_CHECKPOINT_KEY=... python tools/audit_checkpoint.py verify --store checkpoints.jsonl --hashes hashes.tsv
```

كل سطر نقطة يحمل رمز مصادقة (HMAC) بمفتاح خارج المنصة، فيُكشف السطر المزوّر إن لم يكن المخزن إضافة فقط. التحقق يفشل إن تغيّرت بصمة رقم سبق تسجيله (أُعيد بناء السلسلة)، أو اختفى صف مسجل، أو تراجع الرأس. تشغيله يوميًا مسجل في `service/jobs.py`؛ تجهيز المخزن الخارجي خطوة إعداد للمالك.
